WHAT CHANGED

squad_dispatch_static_leaf now knows the contiguous prefix selected by its
descriptor slot. It constructs an equivalent typed cudax view whose local warp
rank is cachedWarpIdx minus that prefix. A debug assertion compares this value
with the original group_as mapping. Arbitrary descriptor IDs remain independent
of partition slots; permuted-ID tests exercise this distinction.

The prior int-inclusive entry executes 10 uniform instructions before the
first reducer body versus 8 selected; scanner warps execute 14 versus 11.
The original baseline executes 5 in either case. These counts include the
resource-offset UIADD shared by both paths and count taken/not-taken branches.
The selected static prologue remains 17 instructions versus prior 23 and
baseline 5. The linear mapper still materializes a dense group rank through
GE4/GE8/NE8/GE10 comparisons plus rank UMOV/USEL operations, then dispatches
from that result. This remaining mapping/count/descriptor control flow is the
main visible abstraction overhead at entry. It is not eliminated in the final
selected version; the 5-instruction reconstruction seen in an earlier binary-
mapper candidate is not the final linear implementation.

Whole-kernel accounting: each of the eight selected scan kernels has 3 fewer
non-NOP instructions than prior. UMOV count drops by 4 and USEL by 1; MOV
count increases by 2. UIADD counts are unchanged overall because scheduling
and address setup elsewhere differ. Padding changes by +3 or -5 per kernel,
so five kernels keep the same padded size and three shrink by 8. The complete
binary decreases by 24 instructions. The int-inclusive padded size remains
1,528, although its non-NOP count decreases by 3.

The binary mapper alone with the previous squad produced 32,912 optional
instructions and 15 indirect branches; adding the rank rebind produced
35,464 optional instructions and 20 indirect branches. Double/affine pipeline
bodies were repeated despite unchanged register/shared-memory allocations.
Explicit constexpr role pruning made this candidate healthy, but it was not
selected because the generic mapper exposed severe callback-codegen sensitivity.
Linear mapper plus role/type index added complexity for only 48 optional
instructions of savings. Partial role pruning and an optional-only gate gave
no better tuple. The selected product retains the linear mapper and rank rebind.

A CUB-only temporary overlay initially reported 13,248 for a prefix rebind,
but it still read a changing working-tree cudax header. It did not isolate the
linear mapper. The source-hashed preflight and exact staged-mapper overlay
corrected this attribution. The generic lane-mask ternary and its if-constexpr
lambda spelling both produced 13,448/13,808 with the final rebind-only squad.
The style rewrite therefore did not explain the difference. The final mapper
restores the original ternary with precise lint annotations; its non-comment
code tokens exactly match the staged original.

Other rejected rank variants:
- threadIdx - 32*(cachedWarpIdx-groupWarpRank): 13,480 instructions in its
  original probe; did not remove the selected-prefix problem.
- cached laneId for laneRank: 13,464 in its original probe, with mixed affine
  register-allocation changes; not selected.
- a separate descriptor-local thread-unit view: some code-size reduction, but
  affine-exclusive allocation reached 128 registers; still 128 after role DCE.
- a scalar cached thread rank: additional callback code or 128-register affine
  allocation persisted after explicit role pruning; not selected.

Validation: selected debug squad checks passed CUDA 13.5/GCC 13 and CUDA
12.0/GCC 7, C++17, including single, uniform, uneven, 1024-thread, subrange,
and permuted descriptor-ID layouts. Full header host/device clang-tidy and

STRUCTURAL DESCRIPTOR-BEFORE-COUNT PROBE (ISOLATED; PRODUCT STILL FROZEN)

A separate overlay keeps the original generic mapper and changes only the CUB
adapter's dispatch order. Balanced thresholds on the cached uniform physical
warp index select the descriptor first. Only that leaf constructs its known
static-count view from Counts[Index] and the corresponding prefix. The actual
group_as partition is still constructed, and debug checks verify both selected
ordinal and local rank against it. Native cudax identity-group synchronization
and public rank queries remain. with_static_unit_count is unnecessary after
the descriptor leaf already establishes the count at compile time.

This avoids the previous count-specialization x descriptor-selection callback
cross-product. The complete 16-kernel CPU probe produced 13,216 main / 13,536
optional instructions, with zero indirect branches, 3 barriers, no stack or
spills, and unchanged sum-kernel register counts (86-89). Affine main uses
96/95 registers versus the selected rank-only 96/93; optional uses 93/95 in
both. The main total equals the original baseline's 13,216 instructions;
individual instruction sequences and dynamic execution still need measurement.

Independent code review found the static positive-count/full-block invariants,
leaf count/rank equivalence, arbitrary descriptor IDs, single/uniform layouts,
and native barrier-ID lifetime sound. Latest and CUDA12 debug squad binaries
compiled, and full header host/device clang-tidy passed. GPU validation and
fresh benchmarks are pending the existing measurement window. The product is
not changed by this probe. Overlay header SHA256 at review freeze:
