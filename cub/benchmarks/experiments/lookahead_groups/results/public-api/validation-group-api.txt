Public group view API validation, 2026-11-11

Implemented public APIs:
  group_view_t<Unit, Group>: host-side type query without a device function body.
  view.with_static_unit_count<N>(): checked explicit compile-time count refinement.
  view.with_unit_rank(rank): checked equivalent cached rank, preserving mapping state.
  View::static_unit_count(): host/device constexpr query, dynamic_extent when unknown.
  Refinement keeps the original underlying group type and synchronizer; no nesting
  or additional instance state. Nonexhaustive invalid views remain invalid.

Compatibility fix:
  this_group, virtual_group, generic_group and coalesced_group rank return types
  are explicit, matching the pre-existing __product_type result exactly. This
  permits namespace-scope view types in nvcc's host pass. Mapping-result type
  computation is a pure trait rather than decltype of an auto device function.
